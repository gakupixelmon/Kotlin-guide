# 動的計画法入門：階段登り問題 (Climbing Stairs)

## 問題文

あなたは $n$ 段の階段を登ろうとしています。あなたは一度に **1段**、または **2段** 登ることができます。
頂上（ $n$ 段目）に到達する方法は何通りありますか？

### 制約
* $n$ は整数
* $1 \le n \le 45$ （答えが 32bit 整数に収まる範囲）

### 入力
* 整数 $n$

### 出力
* 登り方の総数

---

## 解法 (Kotlin)

この問題は、典型的な動的計画法 (DP) の問題です。
$i$ 段目に到達する方法の数を $dp[i]$ と定義すると、以下の漸化式が成り立ちます。

$$dp[i] = dp[i-1] + dp[i-2]$$

なぜなら、 $i$ 段目に到達するには、以下の2つの方法しかないからです。
1.  $i-1$ 段目から 1段登る
2.  $i-2$ 段目から 2段登る

これはフィボナッチ数列と同様の形式です。

### 実装コード

以下のコードでは、配列を使用して計算結果を保持しています。

    fun main() {
        val n = 10 // 例として10段の階段を登る場合
        val ways = climbStairs(n)
        println("階段の段数: $n")
        println("登り方の総数: $ways")
    }

    fun climbStairs(n: Int): Int {
        // ベースケース: 1段または2段の場合は、段数と同じ通りの数になる
        // 1段 -> 1通り (1)
        // 2段 -> 2通り (1+1, 2)
        if (n <= 2) return n

        // DPテーブルの作成 (インデックスを段数と合わせるため n+1 のサイズ)
        val dp = IntArray(n + 1)
        
        // 初期値の設定
        dp[1] = 1
        dp[2] = 2

        // 3段目から n段目まで計算
        for (i in 3..n) {
            dp[i] = dp[i - 1] + dp[i - 2]
        }

        return dp[n]
    }

## 解説

* **時間計算量**: $O(n)$ - ループを $n$ 回回すため。
* **空間計算量**: $O(n)$ - `dp` 配列を使用するため。（変数を2つだけ使う方法にすれば $O(1)$ に最適化可能です）

このアルゴリズムにより、再帰のみで解こうとした場合に発生する指数関数的な計算時間の増大を防ぐことができます。

# 動的計画法（応用）：賢い泥棒の計画 (House Robber)

## 問題文

ある通り沿いに $n$ 軒の家が並んでいます。それぞれの家には特定の金額の現金が保管されています（配列 `nums` で与えられます）。
あなたはプロの泥棒として、これらの家からできるだけ多くの現金を盗みたいと考えています。

しかし、唯一の制約があります。**「隣り合っている2軒の家を同じ夜に盗むと、防犯システムが作動し警察に通報されてしまう」** ということです。

警察に通報されることなく、盗み出せる現金の**最大合計額**を求めてください。

### 例
* 家にある現金: `[1, 2, 3, 1]`
    * 1軒目(1)と3軒目(3)を盗む = 合計 4
    * 2軒目(2)と4軒目(1)を盗む = 合計 3
    * **答え: 4**

* 家にある現金: `[2, 7, 9, 3, 1]`
    * 1軒目(2)、3軒目(9)、5軒目(1) = 合計 12
    * 2軒目(7)、4軒目(3) = 合計 10
    * **答え: 12**

### 制約
* $1 \le nums.length \le 100$
* $0 \le nums[i] \le 400$

---

## 解法 (Kotlin)

この問題のポイントは、「ある家 $i$ を盗むかどうか」の判断が、「2つ前の家の結果」と「1つ前の家の結果」に依存することです。

$i$ 軒目までの最大金額 $dp[i]$ を考えるとき、選択肢は2つだけです：

1.  **$i$ 軒目を盗む**: この場合、隣の $i-1$ 軒目は盗めないので、$i-2$ 軒目までの最大額に、今の家の現金を足します。
    * 式: $dp[i-2] + nums[i]$
2.  **$i$ 軒目を盗まない**: この場合、$i-1$ 軒目までの最大額がそのまま引き継がれます。
    * 式: $dp[i-1]$

この2つのうち、**大きい方**が $dp[i]$ の値になります。

$$dp[i] = \max(dp[i-1], \quad dp[i-2] + nums[i])$$

### 実装コード

    import kotlin.math.max

    fun main() {
        val nums = intArrayOf(2, 7, 9, 3, 1)
        val maxProfit = rob(nums)
        println("家の現金リスト: ${nums.joinToString(", ")}")
        println("盗める最大額: $maxProfit")
    }

    fun rob(nums: IntArray): Int {
        val n = nums.size
        
        // コーナーケース: 家がない、または1軒だけの場合
        if (n == 0) return 0
        if (n == 1) return nums[0]

        // DPテーブルの作成
        // dp[i] は「i番目の家（インデックスi）まで検討した時の最大額」
        val dp = IntArray(n)

        // 初期値の設定
        dp[0] = nums[0]
        // 2軒目までは、どちらか多い方を選ぶしかない
        dp[1] = max(nums[0], nums[1])

        // 3軒目(インデックス2)から最後まで計算
        for (i in 2 until n) {
            // 「盗まない（直前までの最大値を維持）」 vs 「盗む（2つ前 + 現在の額）」
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
        }

        // 最後の要素に最大値が入っている
        return dp[n - 1]
    }

## 解説

* **考え方の転換**: 階段問題では「1歩か2歩か」という**行動の選択**でしたが、この問題では「選ぶか選ばないか」という**状態の選択**になります。しかし、構造（直前を見るか、2つ前を見るか）は非常に似ています。
* **計算量**:
    * 時間計算量: $O(n)$ - 家の数だけループします。
    * 空間計算量: $O(n)$ - 配列 `dp` を使っています。（これも変数2つ `prev`, `curr` だけを使うことで $O(1)$ に最適化可能です）

# 動的計画法（最小化）：コイン問題 (Coin Change)

## 問題文

あなたは $n$ 円の金額を支払う必要があります。
手元には **1円、3円、5円** の3種類の硬貨が無限にあります。
$n$ 円を支払うために必要な硬貨の**最小枚数**を求めてください。

### 例
* 金額 $n = 11$
    * 5円 $\times$ 2枚 + 1円 $\times$ 1枚 = 11円 （合計3枚）
    * **答え: 3**

* 金額 $n = 7$
    * 5円 $\times$ 1枚 + 1円 $\times$ 2枚 = 7円 （合計3枚）
    * または、3円 $\times$ 2枚 + 1円 $\times$ 1枚 = 7円（合計3枚）
    * 1円 $\times$ 7枚 = 7円（合計7枚・最小ではない）
    * **答え: 3**

### 制約
* $1 \le n \le 10^4$

---

## 解法 (Kotlin)

この問題も「1つ前の状態」を利用して解きます。
金額 $i$ 円を作るための最小枚数を $dp[i]$ とします。

$i$ 円を作る直前の手（ラスト1枚）は、以下の3パターンしかありません。
1.  $i-1$ 円の状態から、1円玉を足す $\rightarrow$ 枚数は $dp[i-1] + 1$
2.  $i-3$ 円の状態から、3円玉を足す $\rightarrow$ 枚数は $dp[i-3] + 1$
3.  $i-5$ 円の状態から、5円玉を足す $\rightarrow$ 枚数は $dp[i-5] + 1$

これら3つの候補の中で、**最も小さい値**を選べばよいことになります。

$$dp[i] = \min(dp[i-1], dp[i-3], dp[i-5]) + 1$$

※ただし、$i-3$ や $i-5$ が負になる（インデックス外）場合は無視します。

### 実装コード

    import kotlin.math.min

    fun main() {
        val targetAmount = 11
        val minCoins = coinChange(targetAmount)
        println("目標金額: $targetAmount")
        println("最小硬貨枚数: $minCoins")
    }

    fun coinChange(n: Int): Int {
        // DPテーブルの作成
        // dp[i] は「金額 i を作るのに必要な最小枚数」
        // 初期値として、ありえない大きな数（あるいは n+1 など）を入れておく
        // ここでは n をすべて1円で作った場合の n 枚より大きくなることはないので n + 1 で初期化
        val dp = IntArray(n + 1) { n + 1 }

        // ベースケース: 0円を作るのに必要な枚数は0枚
        dp[0] = 0

        // 使用できる硬貨の種類
        val coins = intArrayOf(1, 3, 5)

        // 1円から n円まで順番に計算
        for (i in 1..n) {
            for (coin in coins) {
                // 硬貨の額面が、現在の金額 i 以下であれば使える
                if (i - coin >= 0) {
                    // 「今の硬貨を使う前の枚数 + 1」と「現在の暫定最小値」を比較
                    dp[i] = min(dp[i], dp[i - coin] + 1)
                }
            }
        }

        return dp[n]
    }

## 解説

* **初期化の重要性**: 「最小値」を求める問題なので、DPテーブルの初期値には「無限大（または解の最大値より大きな値）」を入れておき、`min` 関数で更新されるようにします。
* **計算量**:
    * 時間計算量: $O(n \times k)$ - $n$ は金額、$k$ は硬貨の種類数（ここでは3）。
    * 空間計算量: $O(n)$ - 配列 `dp` のサイズ。

この考え方は、硬貨の種類が `[1, 2, 5, 10, ...]` と増えても全く同じコード（`coins` 配列を変えるだけ）で対応できる汎用性の高いアルゴリズムです。
